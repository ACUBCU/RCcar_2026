## 3. 세부 수행 목표 및 주요 기능

### 3.1. 수행 목표

* 독립된 다중 프로세스를 활용하여 실시간 카메라 이미지 분석 및 장애물 회피 시스템 연동


* 라이다 데이터와 추측 항법(Odometry) 센서 퓨전을 통한 주행 상태 계산 및 공간 추종 로직 구축


* 웹 브라우저 기반의 실시간 2D 호(Right-Arc) 중심 매핑 렌더링 도구 개발



### 3.2. 주요 기능

* 카메라를 활용해 객체 차단 확률이 60% 이상일 때 계단을 감지하는 AI 프로세스 실시간 동작


* 라이다 스캔을 통해 전방, 우측 대각선, 우측 장애물 거리를 계산하여 벽 추종 상태 머신(BACKING_UP, ALIGNING, FOLLOWING) 제어


* 자이로 센서의 각속도 데이터와 모터 구동 속도를 적분하여 로봇 좌표계 내부의 $x$, $y$, $\theta$ 위치 도출


* 웹 캔버스를 활용하여 우측 90도(-135° ~ -45°) 범위 내의 특정 라이다 스캔 포인트만 그리드(Grid) 맵에 시각화

## 4. 시스템 및 하드웨어 구성

### 4.1. 시스템 아키텍처

* `StairDetector` 계단 인식 프로세스와 `LidarExplorer` 자율 주행 프로세스가 병렬 스레드로 분리되어 실행됨


* 각 프로세스는 공유 객체인 `Event`를 활용하여 계단 감지 신호(`stair_event`), 주행 정지 플래그(`stop_event`), 구동 상태(`driving_enabled`)를 동기화함


* Flask 웹 서버 프로세스가 `Queue` 저장소에 비동기적으로 접근하여 로봇 측 데이터를 프론트엔드로 전달함



### 4.2. 하드웨어 구성

* **비전 센서**: 320x240 해상도로 구성된 카메라 모듈이 지속적인 주행 프레임을 분석함


* **라이다 모듈**: 시리얼 포트 `/dev/ttyUSB0` 경로에 마운트되어 있으며 모터 구동 및 정지를 독립적으로 제어받음



---

## 5. 통신 규격 (HTTP/AJAX Payload 구조)

### 5.1. 데이터 송수신 스키마

* 별도의 MQTT 브로커 없이 Flask 애플리케이션의 JSON 엔드포인트를 통신 규격으로 활용함


* **라이다 및 포즈 상태 Payload 예시**:

```json
{
  "pose": {
    "x": 0.12,
    "y": 0.00,
    "theta": 1.5707963267948966
  },
  "state": "FOLLOWING",
  "lidar": [
    {"x": 100.5, "y": -50.2}
  ]
}

```

* 해당 JSON 구조 데이터는 `LidarExplorer` 자율주행 프로세스 내부에서 생성되어 데이터 큐에 삽입됨

## 7. 화면 구성 (UI/UX)

* **좌측 상단 상태 패널**: 로봇의 현재 알고리즘 판별 상태, 수신된 Pose의 X/Y 좌표, 노이즈 필터를 통과한 벽 블록 개수 데이터 표시


* **좌측 하단 제어 버튼**: 자율주행 시스템 시작, 정지, 누적된 지도 메모리 초기화, 캔버스 내 로봇 위치 중앙 고정 버튼 배치


* **슬라이더 설정 패널**: 센서 탐색 거리(0.5~5.0m), 데이터 축적 격자 크기(1~10cm), 맵 출력 최소 필터 노이즈 횟수(1~15회), 시각화 지도 회전 각도 조정기능 제공


* **중앙 캔버스 영역**: 계산된 궤적(Path), 최대 탐색 반경 기준의 반원 형태 호(Arc), 그리드 매핑 로직을 통과한 장애물 좌표를 초당 애니메이션 프레임으로 렌더링

## 8. 핵심 코드 로직 및 데이터 플로우

### 8.1. 핵심 모듈 연산식 및 기능

* **계단 회피 및 방향 추종**: 카메라에 의해 계단 신호가 포착되면 `stair_evasion_mode` 변수를 활성화하여 진입 당시의 차체 각도 $\theta$ 를 메모리에 기록함


* **강제 회피 기동 로직**: 차체가 기록된 시작 각도에서 최단거리 기준 60°($\approx 1.05$ 라디안) 좌회전할 때까지 전방 최소 거리를 380으로 강제 인식시켜 추가 회전을 유도함


* **오도메트리 누적 연산**: 자이로 센서 데이터와 목표 선속도를 바탕으로 회전 반경을 구한 뒤, 매 프레임의 위치 변화량 $dx$, $dy$ 를 누적 계산함


* **공간 필터링 처리**: 수신되는 라이다 배열 중 캔버스 최대 반경(`MAX_RANGE`) 내에 존재하며 우측 대각 방향(-135° ~ -45°) 각도 내에 들어오는 객체만 화면 매핑 데이터 구조에 삽입함



### 8.2. 시스템 운영 사이클

* AI 기반 독립 프로세스가 지속적인 프레임 샘플링을 진행하고, 위험 확률 계산 수치가 0.6 초과 시 공유 이벤트를 트리거함


* 하드웨어 제어 프로세스는 큐 대기열에서 지연 시간을 조율하며 자율주행 알고리즘을 반복 연산하고 센서 데이터를 적재함


* 웹 브라우저는 100ms 주기로 서버 측 데이터 수신부를 호출하여 매핑 배열 및 프레임 버퍼를 비동기 갱신함
